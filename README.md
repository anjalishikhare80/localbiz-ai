# LocalBiz AI

**AI-powered small-business management and business-intelligence platform** — Django · Django REST Framework · PostgreSQL · scikit-learn.

Multi-tenant web app for local shops (stationery, grocery, clothing, electronics, bakery, hardware …): sales and billing, stock ledger, customers and credit, suppliers and purchases, expenses, profit, reports, REST API, and machine-learning insights (demand forecasting, sales forecasting, customer segmentation, unusual-transaction flags, "bought together").

> The demo business is **synthetic data** generated by `seed_demo_data` (clearly labelled in the app). No claims are made about real-world forecast accuracy; see [`docs/ML_AND_ANALYTICS.md`](docs/ML_AND_ANALYTICS.md) for honest evaluation numbers.

---
## 1. Problem
Small shops run on notebooks, WhatsApp and memory. They cannot easily answer: *What is my real profit? What will run out? Who owes me money? Which customers are slipping away? Is any bill unusual?* LocalBiz AI answers these from the shop's own data.

## 2. Features
* **Multi-tenant** — many businesses in one deployment, completely isolated; **roles** Owner / Manager / Employee (+ Django admin for platform staff)
* **Catalog & inventory** — products, categories, suppliers, SKU/barcode, cost & selling price, reorder levels; **append-only stock ledger** (every change recorded with reference, user, time); purchases (stock-in), returns, damages, adjustments; `reconcile_stock` command
* **Sales** — cart-style POS screen with live product search, discounts, tax, partial/credit payments, **one atomic transaction** (sale + items + stock + payment + invoice + audit), cancel with stock restore, **PDF invoices** with safe per-business numbering
* **Customers** — history, lifetime spend, outstanding balance, receive payments (oldest bill first), segment
* **Finance** — expenses with validated private receipts, gross/net profit
* **Dashboard & reports** — KPIs, 30-day chart, top products, low stock, rule-based insights; 9 reports with CSV export (formula-injection safe)
* **AI/ML** — demand forecast (7 d), sales forecast (14 d), RFM + K-Means segmentation, Isolation-Forest "potentially unusual transaction" flags, association rules; model versioning, saved artifacts, honest metrics
* **Notifications** — low stock, forecast shortage, overdue payments (in-app; hourly via Celery or on demand)
* **Audit log** — logins, product/customer/sale/inventory/expense changes, role changes, exports
* **REST API** — JWT, pagination, search, filtering, throttling, consistent errors ([`docs/API.md`](docs/API.md), Postman collection included)
* **Security** — see section 7. **Tests** — 115 automated tests including real concurrent-checkout tests on PostgreSQL.

## 3. Architecture (short)
Modular monolith: Django views + DRF → **service layer** (business rules, transactions) → ORM → PostgreSQL; ML pipelines train offline (command / Celery) and write prediction tables that pages read. Full detail, ER diagram and design decisions: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

```
config/        settings (base/dev/prod/test), urls, celery
accounts/ businesses/ catalog/ inventory/ customers/ sales/ finance/
analytics/ ml/ notifications/ audit/ api/ core/
templates/ static/ docs/ scripts/
```

## 4. Quick start on Windows (step by step)
**Install once:** [Python 3.11 or newer](https://www.python.org/downloads/) (tick *Add python.exe to PATH*), [PostgreSQL 15/16](https://www.postgresql.org/download/windows/) (remember the password you give the `postgres` user), VS Code, Git.

Open the unzipped `localbiz_ai` folder in VS Code → **Terminal → New Terminal** (PowerShell), then:

```powershell
# 1. virtual environment
python -m venv venv
.\venv\Scripts\Activate.ps1          # if blocked: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 2. install packages
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. create the PostgreSQL user + database AND your .env file (asks for the postgres password)
python scripts/setup_env.py

# 4. create tables
python manage.py migrate

# 5. load the synthetic demo shop (~1-2 minutes) and train the ML models
python manage.py seed_demo_data

# 6. run
python manage.py runserver
```
Open <http://127.0.0.1:8000/> and sign in:

| Role | Username | Password |
|---|---|---|
| Owner (sees everything) | `demo_owner` | `Demo@12345` |
| Manager | `demo_manager` | `Demo@12345` |
| Employee (sales only) | `demo_employee` | `Demo@12345` |

These are **demo credentials for local use only**. To start with an empty business instead, skip step 5 and use **Register**.
Create an admin for `/admin/`: `python manage.py createsuperuser`.

If `setup_env.py` cannot reach PostgreSQL it prints the three SQL lines to run manually in *SQL Shell (psql)* and still writes `.env`.

Without PostgreSQL installed you can still run the whole test-suite: `python manage.py test --settings=config.settings.test` (uses SQLite).

## 5. Environment variables (`.env`)
| Variable | Meaning |
|---|---|
| `SECRET_KEY` | Django secret (generated for you; never commit) |
| `DB_NAME` `DB_USER` `DB_PASSWORD` `DB_HOST` `DB_PORT` | PostgreSQL connection |
| `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `USE_HTTPS` | production only |
| `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` | optional Redis (Celery) |

## 6. Everyday commands
```powershell
python manage.py test                       # full suite on PostgreSQL (~90 s)
python manage.py train_models --all         # retrain ML models (or the "Retrain" button as owner)
python manage.py generate_alerts            # create notifications
python manage.py reconcile_stock [--fix]    # verify cached stock == ledger
python manage.py seed_demo_data --reset     # rebuild the demo shop
```
**Optional background jobs (Celery + Redis).** Redis has no official Windows build: run it with Docker (`docker run -p 6379:6379 redis:7`) or WSL2, then in two more terminals:
```powershell
celery -A config worker -l info --pool=solo      # --pool=solo is needed on Windows
celery -A config beat -l info
```
Beat runs alerts hourly and model retraining weekly. The site works fine without Celery.

## 7. Security summary
Password hashing · CSRF on every POST · session + JWT auth · login lockout and API throttling · role-based permissions in one map · **tenant isolation on every query, form and serializer (IDOR → 404)** · CHECK/UNIQUE constraints in the database · row locking against overselling · receipt upload allow-list + magic-number check + random private names · CSV formula-injection guard · no secrets in code (`.env`) · audit log with secret scrubbing · production settings (HTTPS redirect, secure cookies, HSTS) · `check --deploy` clean. Details: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §4–5.

## 8. Testing
115 tests: money & stock calculations, atomic rollback, invoice numbering, profit, ML preprocessing/leakage, forecast selection, segmentation rules, association maths, anomaly detection, API auth/permissions/validation, **Business A can never read or change Business B's data**, employee/manager restrictions, CSRF, concurrent sales on PostgreSQL, and a smoke test that opens every page for every role on the seeded demo shop.

## 9. Deployment
`Dockerfile` + `docker-compose.yml` (PostgreSQL, Redis, web with gunicorn + WhiteNoise, Celery worker and beat):
```powershell
copy .env.docker.example .env.docker      # edit the secrets
docker compose --env-file .env.docker up --build
docker compose --env-file .env.docker exec web python manage.py createsuperuser
```
For a real server use `config.settings.prod` (HTTPS required; leave `USE_HTTPS` unset), set `ALLOWED_HOSTS` and `CSRF_TRUSTED_ORIGINS`, run behind nginx/Caddy with TLS, and back up PostgreSQL. The Docker files are provided as a starting point; they were not executed in the environment where this project was generated.

## 11. Limitations / future work
Single currency (INR) and one flat tax rate (no GST HSN/CGST/SGST filing) · no barcode-scanner hardware integration · no e-mail/SMS delivery of notifications · sale returns are modelled as cancel-sale or stock adjustment · forecasts ignore promotions and stock-outs · validated on synthetic data only · ideas: forecast-vs-actual monitoring page, supplier lead-time tracking, partial sale returns, WhatsApp reminders, an LLM assistant that only calls the existing KPI/report functions.
